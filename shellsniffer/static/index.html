shellSniffer

shellSniffer sniffs through your shells: it watches every command you type in PowerShell, Git Bash, WSL, bash or zsh – together with its output – and turns it into a searchable, topic-based documentation and a daily journal of your work. Everything stays on this machine.

How it works

  • Capture – small hooks in your shell profiles report each finished command and its output to this local server.
  • 🦙 Ollama on / off – the switch on the Ollama chip (top left, also in ⚙ Settings). Disabled: shellSniffer never starts or contacts Ollama; SniffMagic, Sniff logs with shroom and continuous shrooming are then not available. BM25 search, capture and import keep working.
  • Live – the right side shows every command of every open shell as it happens.
  • ✨ SniffMagic – turns your sessions into documentation. Commands are grouped into sessions per shell window (a new one starts after 5 minutes of pause or 25 commands). Click SniffMagic, choose which sessions – a time range such as Today, Last 7 days or your own from/to, or Everything – and start it. A local Ollama model then goes through them one by one and gives each a domain (e.g. Version control), a topic (existing or new), a title and a documentation in ASD-STE100 style (Simplified Technical English, about 80 %): Purpose, numbered Procedure steps and Result. Each step cites its commands, e.g. 3 = command 3 of the session. The documentation is vectorized right away, so the search finds it too (📄 hits). The panel shows beforehand how many sessions are affected; tick re-document to redo sessions that already have a topic. Without Ollama, a simple heuristic names the topics. The model never runs unless you start it here (or use re-cluster).
  • Sniff logs – the upper search field finds commands, output and directories, ranked with BM25 (exact words, no language model). 🦴 SniffOptions holds the search settings: the hybrid balance (slider: more BM25 = exact words, more cosine = meaning) and a time range.
  • 🍄 Ask the shroom – press Enter in Sniff logs with shroom: the chat model answers your question below the field, using only the best matching sessions and commands from your logs, and cites them as 2. Click a source to open its topic. While it works you see the spinning 🍄 – shrooming..
  • 🍄 Sniff logs with shroom – the lower search field runs a hybrid search: besides the exact words (BM25), a local Ollama model compares the meaning, so “remove container” also finds docker rm. Both rankings are merged; every hit shows where it came from (BM25 #n, 🍄 similarity). The first shroom search embeds your commands (a few hundred per search), so it takes a moment; an embedding model such as nomic-embed-text makes it fast. The model only runs while the you search in that field – unless you turn on 🍄 Continuous shrooming in ⚙ Settings: then every new command is vectorized in the background right away, so the shroom always covers all logs. Off by default; the progress is shown next to the switch.
  • Journal – shows which topics you worked on, day by day.

Capture settings (⚙ Settings)

  • With Atuin – Atuin records the commands, shellSniffer reads its history and the hook only adds the output.
  • Without Atuin – shellSniffer ignores Atuin and takes commands and output straight from its own hooks. Everything still goes into the database, the live view and the search.
  • Honeypot log – an extra for Without Atuin (greyed out in ⚙ Settings while With Atuin is selected). When ticked, every shell session is additionally written to its own plain-text file, commands and full output, so you can read, grep or archive it outside shellSniffer. Leave it off if you do not need these files – for example to save disk space or to avoid a second copy of sensitive output.

Where your shell logs are stored

  • Database (all commands, output, sessions, topics): …
  • Honeypot log files (only Without Atuin + Honeypot log ticked), one per shell session, e.g. 2026-11-24_pwsh_MYPC_1234.log: … – …. The folder is created with the first logged command.
  • Temporary output buffers of running shells (ps-transcript-*.txt, typescript-*.log) in …
  • Markdown export (top right) downloads the whole documentation as one file.
  • 📥 Import dumps (top right) loads shell activity someone collected earlier – history files, PowerShell transcripts, terminal logs, honeypot logs, JSON/CSV. The format is detected automatically; imported commands appear as sessions named import:<file>.

Privacy

Passwords, tokens, API keys and similar secrets are masked before anything is stored or sent to the model. To keep a shell out entirely, set SHELLSNIFFER_DISABLE=1 in it.

The gear at the top right holds the general settings, saved on the server so shellSniffer always opens with them: capture with / without Atuin, the honeypot log, the roaming dog on/off, continuous shrooming and the theme.
